Bien sûr ! Dans FreeIPA, l'automount est une fonctionnalité qui permet de configurer et de gérer le montage automatique de systèmes de fichiers (comme NFS) pour les clients Linux. FreeIPA intègre cette fonctionnalité pour centraliser la gestion des points de montage automatiques, ce qui est particulièrement utile dans les environnements d'entreprise avec de nombreux clients et serveurs. Voici une explication détaillée de son fonctionnement :
1. Qu'est-ce que l'automount dans FreeIPA ?

L'automount dans FreeIPA permet de définir des cartes automount (automount maps) qui spécifient où et comment les systèmes de fichiers doivent être montés automatiquement sur les clients. Ces cartes sont stockées dans le répertoire LDAP de FreeIPA, ce qui permet une gestion centralisée et une distribution cohérente aux clients via le protocole SSSD (System Security Services Daemon).

Les cartes automount contiennent :

    Clés : Les points de montage (par exemple, /home, /data).
    Informations de montage : Les détails du serveur et du chemin du système de fichiers à monter (par exemple, serveur:/export/home).

2. Composants principaux

    Automount Maps : Ce sont des conteneurs logiques qui regroupent les configurations de montage. Il existe deux types principaux :
        Direct Maps : Définissent un point de montage spécifique (ex. /home/user).
        Indirect Maps : Définissent un répertoire parent (ex. /home) avec des sous-chemins dynamiques (ex. /home/user1, /home/user2).
    Automount Keys : Une clé correspond à un point de montage spécifique dans une carte.
    Automount Locations : Les emplacements (locations) permettent de regrouper les cartes automount pour des environnements spécifiques (par exemple, un datacenter ou un site géographique).
    SSSD : Le daemon SSSD sur le client récupère les configurations automount depuis le serveur FreeIPA via LDAP et les applique localement.
    autofs : Le service Linux local qui effectue le montage automatique en fonction des configurations reçues.

3. Comment ça fonctionne ?

Voici le processus général de fonctionnement de l'automount dans FreeIPA :

    Configuration sur le serveur FreeIPA :
        L'administrateur crée des cartes automount (directes ou indirectes) dans FreeIPA à l'aide de l'interface web, de la CLI (ipa command) ou de scripts.
        Ces cartes sont stockées dans l'annuaire LDAP de FreeIPA, sous une branche spécifique (par exemple, cn=automount,dc=example,dc=com).
        Chaque carte contient des clés et des informations de montage (par exemple, serveur NFS et chemin d'exportation).
        Les cartes peuvent être associées à une location pour segmenter les configurations par site ou environnement.
    Distribution aux clients :
        Les clients Linux configurés avec FreeIPA (via SSSD) interrogent le serveur LDAP pour récupérer les cartes automount associées à leur emplacement.
        SSSD utilise le module autofs pour traduire les informations LDAP en une configuration compréhensible par le service autofs local.
    Montage automatique sur le client :
        Le service autofs sur le client surveille les répertoires définis dans les cartes automount.
        Lorsqu'un utilisateur ou un processus accède à un répertoire configuré (par exemple, cd /home/user), autofs déclenche le montage du système de fichiers correspondant (par exemple, serveur:/export/home/user).
        Une fois l'accès terminé, autofs peut démonter automatiquement le système de fichiers après un délai d'inactivité pour économiser des ressources.

4. Configuration pratique

Voici les étapes typiques pour configurer l'automount dans FreeIPA :
Étape 1 : Créer une location
bash
ipa automountlocation-add ma-location
Étape 2 : Créer une carte automount

Pour une carte indirecte (par exemple, pour /home) :
bash
ipa automountmap-add-indirect ma-location auto.home --mount=/home

Pour une carte directe (par exemple, pour /data) :
bash
ipa automountmap-add-direct ma-location auto.direct --mount=/data
Étape 3 : Ajouter une clé à la carte

Pour une carte indirecte (par exemple, associer user1 à un montage NFS) :
bash
ipa automountkey-add ma-location auto.home --key=user1 --info=serveur:/export/home/user1

Pour une carte directe :
bash
ipa automountkey-add ma-location auto.direct --key=/data --info=serveur:/export/data
Étape 4 : Configurer le client

    Assurez-vous que le client est enrolé dans FreeIPA et que SSSD est configuré.
    Activez et configurez le module autofs dans /etc/sssd/sssd.conf :
    ini

[sssd]
services = nss, pam, autofs
Redémarrez SSSD et autofs :
bash

    systemctl restart sssd autofs

Étape 5 : Tester

Accédez au répertoire configuré (par exemple, cd /home/user1) et vérifiez que le système de fichiers est monté automatiquement avec df -h.
5. Points importants

    SSSD et autofs : SSSD est essentiel pour récupérer les configurations automount depuis LDAP. Assurez-vous que le client est correctement configuré pour communiquer avec FreeIPA.
    Performance : Les montages automatiques réduisent l'utilisation des ressources, car les systèmes de fichiers ne sont montés qu'à la demande.
    Sécurité : FreeIPA gère les autorisations d'accès via Kerberos, ce qui sécurise les montages NFS (par exemple, en utilisant sec=krb5).
    Flexibilité : Les locations permettent de gérer différents ensembles de cartes pour différents sites ou groupes de machines.
    Dépannage :
        Vérifiez les logs de SSSD (/var/log/sssd/) et d'autofs (/var/log/messages ou /var/log/syslog).
        Assurez-vous que les ports LDAP (389) et, si nécessaire, Kerberos (88) sont ouverts.

6. Exemple concret

Supposons que vous ayez un serveur NFS nfs.example.com qui exporte /export/home. Vous voulez que tous les répertoires sous /home sur les clients soient montés automatiquement.

    Créez une location :
    bash

ipa automountlocation-add datacenter1
Créez une carte indirecte pour /home :
bash
ipa automountmap-add-indirect datacenter1 auto.home --mount=/home
Ajoutez une clé générique pour tous les utilisateurs :
bash
ipa automountkey-add datacenter1 auto.home --key="*" --info=nfs.example.com:/export/home/&
Sur le client, assurez-vous que SSSD et autofs sont configurés, puis testez :
bash

    cd /home/user1
    df -h

Si tout est configuré correctement, /home/user1 sera monté automatiquement depuis nfs.example.com:/export/home/user1.

    Sécurité : Intégration avec Kerberos pour des montages sécurisés.
    Flexibilité : Supporte des configurations complexes avec des cartes directes et indirectes.
    Automatisation : Réduit la charge administrative en automatisant les montages.

1. Configuration résultante sur le poste utilisateur

Lorsqu'un client Linux utilise l'automount avec FreeIPA, la configuration est gérée dynamiquement via SSSD et autofs. Voici ce qui se passe sur le poste utilisateur :
a) Rôle de SSSD

    SSSD (System Security Services Daemon) est le composant clé qui fait le lien entre FreeIPA (LDAP) et le client. Il récupère les cartes automount depuis le serveur FreeIPA via LDAP et les traduit en un format compréhensible par le service autofs.

    SSSD utilise son module autofs pour fournir les informations de montage à autofs. Ces informations incluent :
        Les cartes automount (directes ou indirectes).
        Les clés (points de montage comme /home/user1).
        Les informations de montage (par exemple, serveur:/export/home/user1).

    La configuration de SSSD est généralement définie dans le fichier /etc/sssd/sssd.conf. Voici un exemple de section pertinente :
    ini

    [sssd]
    services = nss, pam, autofs
    domains = example.com

    [domain/example.com]
    id_provider = ipa
    auth_provider = ipa
    access_provider = ipa
    autofs_provider = ipa
        autofs_provider = ipa indique que SSSD récupère les cartes automount depuis le serveur FreeIPA.
        SSSD met en cache ces informations localement pour améliorer les performances et permettre un fonctionnement hors ligne temporaire (si configuré).

b) Rôle de autofs

    Le service autofs est responsable de surveiller les répertoires configurés comme points de montage et de déclencher le montage des systèmes de fichiers à la demande.

    Les cartes automount récupérées par SSSD sont accessibles via le fournisseur autofs de SSSD, qui agit comme une source de données pour autofs.

    Sur le client, autofs ne stocke pas directement les cartes dans des fichiers statiques comme /etc/auto.master ou /etc/auto.* (contrairement à une configuration autofs traditionnelle). Au lieu de cela, il utilise une interface dynamique via SSSD, souvent référencée comme sss dans la configuration d'autofs.

    Exemple de configuration dans /etc/auto.master :
    text

    /home   program:/usr/libexec/sssd/sss_autofs   --timeout=300
        Ici, /home est le répertoire parent pour une carte indirecte.
        program:/usr/libexec/sssd/sss_autofs indique qu'autofs doit interroger SSSD pour obtenir les détails des montages.

    Une fois configuré, le service autofs surveille les accès aux répertoires (par exemple, cd /home/user1), récupère les informations de montage via SSSD, et monte le système de fichiers correspondant (par exemple, serveur:/export/home/user1).

c) Fichiers et services impliqués

    Fichiers de configuration :
        /etc/sssd/sssd.conf : Configure SSSD pour récupérer les cartes automount depuis FreeIPA.
        /etc/auto.master : Spécifie les répertoires parents (comme /home) et le programme utilisé (souvent SSSD).
        /etc/autofs.conf : Contient les paramètres globaux d'autofs, comme les délais de démontage (timeout).
    Services actifs :
        sssd : Doit être en cours d'exécution pour fournir les cartes automount.
        autofs : Doit être en cours d'exécution pour surveiller et effectuer les montages automatiques.

d) Résultat sur le client

    Lorsqu'un utilisateur accède à un répertoire configuré (par exemple, cd /home/user1), autofs détecte l'accès, SSSD fournit les détails du montage (par exemple, serveur:/export/home/user1), et le système de fichiers est monté automatiquement.
    Une fois l'accès terminé, autofs démonte le système de fichiers après un délai d'inactivité (configurable dans /etc/autofs.conf).
    Aucun fichier statique comme /etc/auto.home n'est créé manuellement, car les informations sont récupérées dynamiquement depuis FreeIPA via SSSD.

C’est quoi la différence entre map direct et indirect ?

Dans le contexte de l'automount avec FreeIPA (ou autofs en général), la différence entre une carte directe (direct map) et une carte indirecte (indirect map) réside dans la manière dont les points de montage sont définis et gérés sur le client. Voici une explication claire et concise de leurs différences :
1. Carte directe (Direct Map)

    Définition : Une carte directe associe un point de montage spécifique et fixe à une ressource (par exemple, un répertoire NFS). Le chemin complet du point de montage est explicitement défini dans la carte.
    Caractéristiques :
        Le point de montage est un chemin absolu unique (par exemple, /data, /mnt/partage).
        Chaque clé dans la carte directe correspond à un point de montage spécifique.
        Les montages directs sont indépendants les uns des autres et ne partagent pas un répertoire parent commun.
    Exemple :
        Configuration dans FreeIPA :
        bash

        ipa automountmap-add-direct ma-location auto.direct --mount=/data
        ipa automountkey-add ma-location auto.direct --key=/data --info=serveur:/export/data
        Résultat sur le client : Lorsque l'utilisateur accède à /data, le système de fichiers serveur:/export/data est monté directement à cet emplacement.
    Utilisation :
        Utile pour des montages spécifiques et statiques où chaque point de montage correspond à une ressource unique.
        Par exemple : /mnt/backup, /var/log/archive.

2. Carte indirecte (Indirect Map)

    Définition : Une carte indirecte définit un répertoire parent commun (par exemple, /home), et les sous-répertoires (ou clés) sous ce parent sont montés dynamiquement en fonction des clés définies dans la carte.
    Caractéristiques :
        Le répertoire parent est spécifié dans la carte (par exemple, /home), et les clés représentent des sous-chemins relatifs (par exemple, user1, user2).
        Les montages sont déclenchés uniquement lorsque l'utilisateur accède à un sous-répertoire spécifique (par exemple, /home/user1).
        Les cartes indirectes permettent de gérer dynamiquement un grand nombre de montages sous un même répertoire parent.
        Les clés peuvent inclure des motifs génériques (par exemple, *) pour correspondre à des sous-répertoires dynamiques.
    Exemple :
        Configuration dans FreeIPA :
        bash

        ipa automountmap-add-indirect ma-location auto.home --mount=/home
        ipa automountkey-add ma-location auto.home --key=user1 --info=serveur:/export/home/user1
        ipa automountkey-add ma-location auto.home --key=* --info=serveur:/export/home/&
        Résultat sur le client :
            Si l'utilisateur accède à /home/user1, serveur:/export/home/user1 est monté.
            Avec la clé *, tout accès à /home/<nom> tente de monter serveur:/export/home/<nom>.
    Utilisation :
        Idéal pour les environnements où de nombreux utilisateurs ou ressources partagent un répertoire commun, comme les répertoires personnels (/home).
        Par exemple : Monter les répertoires personnels de tous les utilisateurs depuis un serveur NFS.

3. Différences clés
Critère	Carte directe	Carte indirecte
Point de montage	Chemin absolu spécifique (ex. /data)	Sous-répertoire sous un parent commun (ex. /home/user1)
Répertoire parent	Aucun répertoire parent commun	Nécessite un répertoire parent (ex. /home)
Flexibilité	Moins flexible, chaque montage est explicite	Très flexible, supporte des clés dynamiques (ex. *)
Configuration	Une entrée par point de montage	Une seule carte pour plusieurs sous-répertoires
Exemple d'utilisation	Montage unique comme /mnt/backup	Répertoires personnels comme /home/userX
Fichier auto.master	Contient des entrées spécifiques (ex. /data)	Contient un répertoire parent (ex. /home)

Carte directe :

    Configuration : /data monte serveur:/export/data.
    Dans /etc/auto.master (ou via SSSD) :
    text

/-  /etc/auto.direct
Dans auto.direct (ou via FreeIPA) :
text

    /data  serveur:/export/data
    Résultat : L'accès à /data monte directement serveur:/export/data.

Carte indirecte :

    Configuration : /home contient des sous-répertoires comme user1, user2, etc.
    Dans /etc/auto.master (ou via SSSD) :
    text

/home  /etc/auto.home
Dans auto.home (ou via FreeIPA) :
text

    user1  serveur:/export/home/user1
    user2  serveur:/export/home/user2
    *      serveur:/export/home/&
    Résultat : L'accès à /home/user1 monte serveur:/export/home/user1, et la clé * permet de gérer dynamiquement tout utilisateur.

5. Quand utiliser l'un ou l'autre ?

    Carte directe : Utilise-la pour des montages statiques et uniques qui ne partagent pas une structure de répertoire commune (par exemple, un répertoire de sauvegarde ou une ressource spécifique).
    Carte indirecte : Utilise-la pour des montages dynamiques où plusieurs sous-répertoires doivent être gérés sous un même répertoire parent, comme les répertoires personnels ou des partages multiples.

a) Options de montage NFS

Dans FreeIPA, les cartes automount (directes ou indirectes) incluent une option --info où tu spécifies les détails du montage, comme le serveur et le chemin.
Pour NFS, tu peux ajouter des options de montage qui affectent les permissions des fichiers montés. Par exemple :
bash

chmod -R u=rwx,g=rx,o= /export/home


Ou utilise des ACL pour des permissions plus fines.

b) Utiliser mode ou fmask/dmask (pour d'autres systèmes de fichiers)

Si tu montes des systèmes de fichiers autres que NFS (par exemple, CIFS/SMB via automount), tu peux spécifier des options comme file_mode et dir_mode pour contrôler les permissions des fichiers et répertoires :

ipa automountkey-add ma-location auto.direct --key=/mnt/partage --info="serveur:/partage,file_mode=0640,dir_mode=0750"

Cependant, cela ne s'applique pas directement à NFS, car NFS repose sur les permissions du serveur.

c) Configurer l'umask sur le serveur NFS

Si tous les utilisateurs doivent avoir une umask spécifique pour les fichiers créés sur le partage NFS, configure l'umask sur le serveur NFS pour le processus exportant le répertoire (par exemple, dans /etc/profile ou un script de démarrage pour le service NFS).
Alternativement, utilise des options comme anonuid et anongid dans /etc/exports pour forcer un utilisateur ou groupe spécifique, ce qui peut indirectement contrôler les permissions :
/export/home *(rw,sec=krb5,anonuid=1000,anongid=1000)

3. Résumé des possibilités

Dans FreeIPA directement : Pas de support natif pour définir l'umask des utilisateurs dans l'annuaire LDAP. Tu peux contourner cela en configurant les clients via des fichiers de profil (/etc/profile, /etc/login.defs) ou PAM (pam_umask).
Au niveau du montage automount : L'umask n'est pas directement configurable dans les montages NFS, mais tu peux contrôler les permissions via :

Les options de montage (file_mode, dir_mode pour CIFS, mais pas NFS).
Les permissions sur le serveur NFS (par exemple, umask ou ACL sur le répertoire exporté).


Centralisation : Pour une gestion centralisée, utilise des outils comme Ansible pour déployer des configurations d'umask sur tous les clients, ou configure le serveur NFS pour imposer des permissions cohérentes.
/export/home *(rw,sec=krb5)

ipa automountmap-add-indirect ma-location auto.home --mount=/home

6. Conclusion

Umask des utilisateurs : Gère-la au niveau des clients via /etc/profile, /etc/login.defs, ou PAM (pam_umask). FreeIPA ne permet pas de la définir directement dans l'annuaire.
Umask au niveau du montage : Pour NFS, contrôle les permissions via le serveur NFS (permissions des répertoires exportés ou options dans /etc/exports). Pour d'autres systèmes de fichiers comme CIFS, utilise file_mode/dir_mode dans les options de montage.

Si tu as un cas d'utilisation spécifique (par exemple, un type de montage particulier ou un besoin d'umask par utilisateur), ou si tu veux des détails sur la configuration d'un outil spécifique (Ansible, PAM, NFS), fais-moi signe !
